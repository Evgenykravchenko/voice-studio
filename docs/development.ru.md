## Устройство проекта

| Часть | За что отвечает |
| --- | --- |
| `frontend/` | React, TypeScript и Vite: браузерный интерфейс. |
| `server/` | Java 21 и Spring Boot: локальный API, проверка запросов, очередь и метаданные. |
| `src/voice_cloner/` | Python: модели, обработка аудио, каталог и окружения. |
| `engines/` | Закреплённые зависимости, рецепты исходников и проверенные native wheels. |
| `vendor/` | Сторонний код моделей и его лицензии. |

Обычно Java раздаёт собранный интерфейс и API на порту 4173. Node нужен для
сборки, а не как ещё один рабочий сервис. Python запускается по необходимости,
задания идут по одному. SQLite встроена: PostgreSQL и Redis не требуются.

Поддержка Windows/Linux запланирована. Интерфейс и Java API отделены от моделей, но
нынешние MLX-бэкенды и установка рассчитаны на Apple Silicon. Для других ОС
нужны подходящие движки, установщики и проверка на этих платформах.

## Локальная разработка

Пройдите [обычную установку](setup.ru.md). Остановите обычный режим и запустите разработку:

```sh
./scripts/studio.sh --dev
```

Vite работает на порту 4173, Java на 7080. Зависимости остаются в проекте.
Не перезаписывайте работающий JAR: скрипт сборки проверяет это условие.

Нужные проверки запускаются из корня:

```sh
./.venv/bin/python -m unittest discover -s tests
./scripts/server.sh test
./.runtime/toolchains/node/bin/node --test frontend/tests/*.test.mjs
```

Проверки упаковки ожидают сборку интерфейса после установки. Java JAR собирается
через `./scripts/server.sh build` на остановленной студии. Для frontend-скриптов
используйте локальные Node/pnpm; см. [заметки об интерфейсе](../frontend/README.ru.md).
Проверки реальных моделей в `scripts/verify-*.py` могут требовать много памяти,
места и времени. Используйте отдельные тестовые данные, не личные проекты.

## CLI по желанию

Для обычной работы достаточно интерфейса. CLI использует Fish; выбор другой
модели в веб-приложении не переключает его движок.

```sh
./voice doctor
./voice profile list
./voice generate --help
```

Профили приложения доступны в списке CLI. Используйте настоящий ID из списка.
Отдельный профиль из файла можно подготовить так:

```sh
./voice profile create narrator --audio sample.wav --duration 20
./voice generate --profile narrator --text "Добро пожаловать в студию."
```

Проверьте расшифровку образца. Не запускайте CLI-генерацию одновременно
с заданиями моделей в студии.
