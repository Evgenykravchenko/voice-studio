# Политика безопасности

[English](SECURITY.md) · **Русский** · [Участие в проекте](CONTRIBUTING.ru.md)

## Как сообщить об уязвимости

Используйте [приватный отчёт GitHub](https://github.com/Evgenykravchenko/voice-studio/security/advisories/new).
Укажите версию или коммит, компонент, последствия и минимальные шаги повторения
с обезличенными данными. Не публикуйте ключи, личные записи и готовые эксплойты
в открытых issues и обсуждениях. Отчёты рассматриваются вручную.

## Версии

Voice Studio 0.1.0 поддерживает macOS 14+ на Apple Silicon. Проверяйте текущую `main` или последний опубликованный выпуск. Указывайте точную версию или коммит. Поддерживаемые ветки будут обозначаться в заметках выпуска; постоянный график поддержки и гарантированное время ответа пока не обещаются.

## Границы системы

Приложение состоит из браузерного интерфейса, локального Java API и процессов
Python с моделями. API настроен на loopback. GitHub Pages размещает только
публичную документацию, а не модели, обработку или пользовательские данные.
Публичное размещение приложения для нескольких пользователей не поддерживается.

Защищаемые данные включают записи, расшифровки, профили голосов, проекты, кэши
моделей и целостность кода, workflows, тегов и файлов релиза. Загрузка аудио,
тексты, имена файлов, идентификаторы профилей, скачанные файлы моделей и изменения
кода пересекают границы доверия. Локальный запуск не делает безопасными
вредоносные веб-запросы, ошибки обработки файлов и выход за разрешённые пути.

## Какие свойства нужно сохранять

- Обработка и личные данные остаются локально; записи и тексты не отправляются неожиданно в сеть.
- Проверяются origin и host локальных запросов; loopback не заменяется публичным адресом незаметно для пользователя.
- Доступ к файлам и аргументы процессов ограничены назначением операции. При создании производных записей исходники сохраняются.
- Скачанные файлы и зависимости остаются внутри проекта; закреплённые артефакты моделей проверяются там, где это поддерживается. Уведомления о лицензиях сохраняются.
- Личные данные, ключи, модели и базы не попадают в Git и сборки. Проверяется фактический состав публикации, помимо правил исключения файлов.
- Изменения проходят pull request и обязательные проверки. Недоверенные workflows участников не получают токены записи и секреты репозитория.
- Выпуски собираются из рассмотренных исходников. Версионные теги и целостность файлов релиза защищаются.

Это свойства для проверки, а не утверждение о полном аудите каждого пути кода.
Сообщайте об обходах с реальной достижимостью и последствиями: раскрытии данных,
чтении или записи файлов, выполнении команд, небезопасной обработке моделей
и архивов, подмене изменений или релизов. Документ не исключает целые классы
уязвимостей из рассмотрения.

## Ограничения

У моделей, зависимостей и сторонних окружений отдельные лицензии и свойства
безопасности. За резервные копии локальных данных отвечает пользователь.
Качество озвучки и успешный CI не доказывают безопасность. Правила репозитория
не заменяют защиту GitHub-аккаунта владельца и его средств доступа.
